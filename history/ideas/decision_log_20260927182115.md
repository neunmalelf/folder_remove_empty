# Decision log — folder_remove_empty, Python + tkinter port

Turns `todo/goal.md` §10 ("Resolved open questions") into a readable log. Every
entry restates a decision that was already taken and its reason; nothing new is
decided here. Recorded 2026-09-27 (local time).

## Resolved questions

### Distribution name
**Decision:** `folder_remove_empty` everywhere — `pyproject.toml` `name`, the
module names, the launcher and `make install`.
**Reason:** one spelling for the whole project; the earlier
`folder-remove-empty` form is dropped, and setuptools normalizes the wheel name
anyway.

### ddpico/Go copies of the root files
**Decision:** rewrite `pyproject.toml`, `README.md`, `ChangeLog.md`, `NEWS` and
the `Makefile` in place.
**Reason:** every ddpico console script and `[tool.*]` section is dead weight in
this project; nothing is left behind as a stub.

### Version identity under PEP 440
**Decision:** one literal `__VERSION__ = "x.y.YYYYMMDDhhmmssZ"` in
`remove_empty_folder_version.py`, the derived `__version__` without the `Z`, and
`pyproject.toml` reads the derived form through `[tool.setuptools.dynamic]`.
**Reason:** `_check_version` requires the repository stamp with the trailing
`Z`, setuptools rejects that exact string (`InvalidVersion`), so one literal
serves both forms and a test pins the pair.

### Python floor
**Decision:** `>=3.13`, with ruff `target-version = "py313"`, 3.13 classifiers
and `mypy python_version = "3.13"`.
**Reason:** the floor matches the build toolchain — `nuitka`, used by `_build`,
supports only 3.13.

### Man page location
**Decision:** `man/folder_remove_empty.1`, generated by `--print-man`.
**Reason:** the Go tree's location, so the two trees stay comparable.

### Repository scripts
**Decision:** keep and adapt `_check_version`, `_skill_sync`, `_tests`,
`_build`, `_install`, `_menu`, `_run` and `_git`; only `_docs` is deleted.
**Reason:** the ddpico assumptions (program table, `dd*` paths, unittest
discovery, local-time stamp, speech calls) are replaced by this project's;
`_check_version` and `_skill_sync` are project-agnostic and stay untouched.

### Desktop launcher
**Decision:** ship `assets/folder_remove_empty.desktop`, installed into
`~/.local/share/applications/` and validated with `desktop-file-validate` when
available.
**Reason:** the spec installs icons so launchers find every size, which needs a
launcher file to go with them.

### Documentation site
**Decision:** dropped — `_docs` and `mkdocs.yml` are deleted.
**Reason:** the man page, the tldr page and `README.md` carry the documentation;
`assets/folder-remove-icon.svg` stays as the vector original of the icon set.

### Settings file
**Decision:** `~/.config/folder_remove_empty/folder_remove_empty.conf`, INI
through `configparser`, written by the window on close and read by both front
ends as the lowest-precedence pre-fill (the command line wins).
**Reason:** spec §5.8 asks for a persisted geometry and program settings file.

### ddpico-only skills
**Decision:** prune and retarget them now, not in phase 6: `dd-module-topics`
and `ddtoolbox-fart` are deleted, and `tests-subfolder`,
`skill_docstring_format`, `update-docs`, `update-pyproject`, `update-tests` are
retargeted to the flat modules, the `tests/folder_remove_empty/` subtree and the
Makefile — 15 skills left, `./_skill_sync --check` green.
**Reason:** a rule marked `always` that contradicts the code layout is worse
than no rule at all.

### Reference captures
**Decision:** the Go binary was built once
(`go build -p 1 ./cmd/folder_remove_empty`) and its output captured into
`tests/folder_remove_empty/reference/`: 13 cases with stdout, stderr and exit
status, plus `cases.md` and a committed `build_tree.sh`; `test_reference.py`
rebuilds that tree and compares both streams byte for byte.
**Reason:** a fixed point outside the port itself is the only proof of
behavioural fidelity; the single initial difference, the reason text of one
refused removal, was aligned to the Go shape because `project_specs.md` §4
leaves the wording open.

### Verification
**Decision:** every layer is checked against a fixed point rather than its own
assumptions: `./_tests` (142 tests, 107 subtests), the byte-for-byte reference
comparison of `TerminalReporter` and `main()`, a real terminal run that removed
a nested chain deepest first, a `pip install .` into a clean venv whose console
script reproduced the captured `--help`/`--print-tldr`, a window probe that
opened the real window, read the nine rows, drove a scripted run, toggled the
theme and read the settings written on close, and a launch through the installed
script that stayed open until the timeout killed it (exit 124, both streams
empty).

### Pre-commit hook
**Decision:** installed with `bash hooks/install.sh`, so every commit here runs
`version`, `skill_sync`, `ruff`, `mypy`, `tests` and `docs` (generated man/tldr
pages vs. the program) before `build` and `directory_hooks`.

## Deliberate differences from the Go original

- The version stamp carries the trailing `Z` (`_check_version` convention); the
  packaging form drops it as `__version__` for PEP 440.
- The man page names the port: its SEE ALSO says the program is the Python port
  of the shell script `_folder_remove_empty` (0.6.20260923165923) it replaced.
- The reason text of a refused removal follows the Go wording
  `remove <path>: <strerror>`.
- The folder dialog is Tk's own `tkinter.filedialog.askdirectory`, not a desktop
  helper such as the Go tree's `zenity`/`kdialog`.
